Become a Verifier

Verifiers protect the publisher registry by independently confirming that a site really placed the Congrid badge. Accurate and timely verifiers earn a share of rewards.

Why run a verifier?

  • Earn rewards: paid for accuracy, coverage, latency, and freshness.
  • Strengthen the network: keep the registry honest and resistant to spam.
  • Low overhead: verification is lightweight compared to full crawling/indexing.

How it works

  • Bond tokens to become eligible (escrow).
  • Run a verifier agent that follows on-chain assignments.
  • Fetch publisher homepages and validate the badge.

Bonding (escrow)

Verifiers participate with a normal account address. To be considered eligible, you bond tokens into the verifier escrow. 

./content-grid-d verifier bond 1000000 \
  --denom ucongrid \
  --from <key>

# Later
./content-grid-d verifier unbond 1000000 \
  --denom ucongrid \
  --from <key>

Run the verifier daemon

The repository includes a chain-driven publisher verification agent (offchain/verifierd). Expect this to evolve quickly as testnet infrastructure lands.

Early operators wanted: If you can run always-on infrastructure and provide feedback, you’ll help shape verifier incentives and APIs.
